Install the standalone binary for everyday use. Contributor and from-source setup is under [For contributors](#for-contributors).

## Supported platforms

| Platform                    | Curl installer | Release archive |
| --------------------------- | -------------- | --------------- |
| Linux amd64 / arm64         | Yes            | Yes             |
| macOS Intel / Apple Silicon | Yes            | Yes             |
| Windows x86_64              | No             | Yes (`*.zip`)   |

The installer requires `bash`, `curl`, `tar`, and either `sha256sum` or `shasum`. Pipe into `bash`, not `sh`.

MongoScope itself does not require `sudo`. If Welcome must list a root-owned log directory such as `/var/log/mongodb`, `sudo` must be on `PATH` for the optional elevate path — see [Permissions and elevated access](/docs/getting-started#permissions-and-elevated-access).

## Install with the curl installer

1. Run the installer:

```bash
curl -fsSL https://raw.githubusercontent.com/prodioslabs/mongoscope/main/install.sh | bash
```

2. Confirm the binary is on your `PATH`:

```bash
mongoscope --version
```

The script detects OS and architecture (`linux` / `darwin` × `amd64` / `arm64`), downloads the matching archive from the latest GitHub Release, verifies it against `checksums.txt`, and installs to `$PREFIX/bin/mongoscope`. It does not modify your shell `PATH`; if `$PREFIX/bin` is missing from `PATH`, the installer prints a warning.

| Platform | Default `$PREFIX` | Default binary path         |
| -------- | ----------------- | --------------------------- |
| Linux    | `/usr/local`      | `/usr/local/bin/mongoscope` |
| macOS    | `$HOME/.local`    | `~/.local/bin/mongoscope`   |

### Optional installer environment variables

| Variable             | Effect                                                                  |
| -------------------- | ----------------------------------------------------------------------- |
| `MONGOSCOPE_VERSION` | Pin a release tag (for example `v0.3.0`). Default: `latest`.            |
| `MONGOSCOPE_PREFIX`  | Install under `$MONGOSCOPE_PREFIX/bin` instead of the platform default. |

Pin a version or a custom prefix:

```bash
MONGOSCOPE_VERSION=v0.3.0 curl -fsSL https://raw.githubusercontent.com/prodioslabs/mongoscope/main/install.sh | bash

MONGOSCOPE_PREFIX=$HOME/.local curl -fsSL https://raw.githubusercontent.com/prodioslabs/mongoscope/main/install.sh | bash
```

## Install from GitHub Releases

Use this path when you prefer not to pipe a script into bash, or when you need Windows.

1. Download the archive for your platform from [GitHub Releases](https://github.com/prodioslabs/mongoscope/releases).
2. Optional: verify the archive against `checksums.txt` from the same release.
3. Extract the archive and place the binary on your `PATH`.

Asset names use the version **without** the `v` prefix (tag `v0.3.0` → `0.3.0` in the filename):

| Platform            | Archive                                    |
| ------------------- | ------------------------------------------ |
| Linux x86_64        | `mongoscope_<version>_linux_amd64.tar.gz`  |
| Linux arm64         | `mongoscope_<version>_linux_arm64.tar.gz`  |
| macOS Intel         | `mongoscope_<version>_darwin_amd64.tar.gz` |
| macOS Apple Silicon | `mongoscope_<version>_darwin_arm64.tar.gz` |
| Windows x86_64      | `mongoscope_<version>_windows_amd64.zip`   |

Example URLs for tag `v0.3.0`:

```text
https://github.com/prodioslabs/mongoscope/releases/download/v0.3.0/mongoscope_0.3.0_linux_amd64.tar.gz
https://github.com/prodioslabs/mongoscope/releases/download/v0.3.0/mongoscope_0.3.0_linux_arm64.tar.gz
https://github.com/prodioslabs/mongoscope/releases/download/v0.3.0/mongoscope_0.3.0_darwin_amd64.tar.gz
https://github.com/prodioslabs/mongoscope/releases/download/v0.3.0/mongoscope_0.3.0_darwin_arm64.tar.gz
https://github.com/prodioslabs/mongoscope/releases/download/v0.3.0/mongoscope_0.3.0_windows_amd64.zip
https://github.com/prodioslabs/mongoscope/releases/download/v0.3.0/checksums.txt
```

On Unix, the archive contains a `mongoscope` binary at the root:

```bash
tar -xzf mongoscope_0.3.0_linux_amd64.tar.gz
sudo install -m 755 mongoscope /usr/local/bin/mongoscope
```

On macOS without `sudo`, install under a user-writable prefix instead:

```bash
install -m 755 mongoscope ~/.local/bin/mongoscope
```

On Windows, unzip `mongoscope_<version>_windows_amd64.zip` and put `mongoscope.exe` on your `PATH`.

## Verify the install

```bash
mongoscope --version
```

Release binaries print the embedded release version and exit. Development builds fall back to the `package.json` version.

## Update MongoScope

Re-run the [curl installer](#install-with-the-curl-installer). The installer replaces `$PREFIX/bin/mongoscope` in place. There is no separate update command.

To pin an upgrade to a known tag:

```bash
MONGOSCOPE_VERSION=v0.3.0 curl -fsSL https://raw.githubusercontent.com/prodioslabs/mongoscope/main/install.sh | bash
```

## Uninstall MongoScope

The installer only writes the binary. There is no uninstall script. Remove that file:

```bash
# Linux default
sudo rm /usr/local/bin/mongoscope

# macOS default
rm ~/.local/bin/mongoscope

# Custom prefix
rm "$MONGOSCOPE_PREFIX/bin/mongoscope"
```

## Troubleshooting

### `mongoscope: command not found` after a successful install

**Symptom:** The installer finished, but the shell cannot find `mongoscope`.

**Cause:** `$PREFIX/bin` is not on your `PATH`.

**Resolution:** Add the install directory to `PATH` (macOS default shown), then confirm with `which mongoscope`:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

Put that line in your shell profile so it persists.

### Permission denied or sudo prompt on Linux

**Symptom:** The installer asks for `sudo`, or fails to write under `/usr/local`.

**Resolution:** Install under a directory you own, or run as root:

```bash
MONGOSCOPE_PREFIX=$HOME/.local curl -fsSL https://raw.githubusercontent.com/prodioslabs/mongoscope/main/install.sh | bash
```

If neither root, `sudo`, nor a writable prefix is available, the installer exits with: `run as root, install sudo, or set MONGOSCOPE_PREFIX to a writable directory`.

### `unsupported OS: …`

**Symptom:** The curl installer rejects the OS.

**Resolution:** The installer supports Linux and macOS only. For Windows, download `mongoscope_<version>_windows_amd64.zip` from [GitHub Releases](https://github.com/prodioslabs/mongoscope/releases).

### `unsupported architecture: …`

**Symptom:** The installer rejects the CPU architecture.

**Resolution:** Only `x86_64` / `amd64` and `aarch64` / `arm64` are published. Other architectures are not available as release archives.

### `run with bash (e.g. curl … | bash)`

**Symptom:** The script exits immediately when piped into `sh`.

**Resolution:** Use `| bash`. The script requires Bash features such as `pipefail`.

## For contributors

You need [Bun](https://bun.sh). A MongoDB log file and a reachable instance are optional depending on what you test.

1. Clone and install dependencies:

```bash
git clone https://github.com/prodioslabs/mongoscope.git
cd mongoscope
bun install
```

2. Launch the TUI from source. The bundled synthetic log opens Slow Queries and Logs without a server:

```bash
bun start --log-path examples/mongod.log.sample
```

Optional: expose `mongoscope` on your `PATH` for local development (requires Bun on `PATH`):

```bash
bun link
mongoscope --help
```

That path is separate from release binaries:

| Script                               | Purpose                                                             |
| ------------------------------------ | ------------------------------------------------------------------- |
| `bun start`                          | Launch the TUI from source                                          |
| `bun link`                           | Expose `mongoscope` on `PATH` for local development                 |
| `bun run build`                      | Native-platform binary → `dist/mongoscope`                          |
| `bun run build:release`              | All five targets + archives + `checksums.txt` under `dist/release/` |
| `bun run typecheck`                  | Typecheck                                                           |
| `bunx oxlint` / `bunx oxfmt --check` | Lint / format check                                                 |
| `bun run test`                       | Vitest                                                              |

Docs site (this site): `cd docs && bun install && bun run dev`.

Pull request checks, project layout, commit format, and the release process: [CONTRIBUTING.md](https://github.com/prodioslabs/mongoscope/blob/main/CONTRIBUTING.md).
